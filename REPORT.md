# REPORT — САП КОД AI-разработчик

1. **Что было сломано:** обработчик безусловно сохранял каждое событие как новую заявку
   и создавал уведомление при каждой доставке. Отсутствовали проверка обязательных полей,
   проверка строкового типа и удаление пробелов. В исходной версии проходили 2 из 8 тестов.

2. **Что исправлено:**
   - Все четыре поля проверяются до открытия БД: обязательны строки, непустые после `strip()`.
     Некорректные события, включая вход не в виде словаря, возвращают `invalid` с понятной причиной.
   - Нормализация сохраняет регистр, внутренние пробелы и исходный словарь вызывающего кода.
   - Уникальный индекс по `(source, external_id)` защищает от повторной вставки.
     `ON CONFLICT (source, external_id) DO NOTHING` обрабатывает именно конфликт этой пары;
     при повторе возвращается существующий ID, первоначальные данные не обновляются.
   - Новая заявка и уведомление создаются в одной транзакции; ошибка уведомления откатывает заявку.
     Подготовка схемы выполняется до транзакции обработки. Соединения явно закрываются.
   - Добавлены 2 дополнительных теста.
     Все проверки 8 исходных тестов сохранены;
     в исходных тестах исправлено только закрытие соединений и обновлено описание модуля.

3. **Как проверено:**

   ```bash
   .venv/bin/python -W error::ResourceWarning -m unittest discover -s tests -v
   ```

   Результат: 10 тестов, все прошли. Два дополнительных теста проверяют все обязательные поля
   (32 варианта через `subTest`) и сохранение нормализованных значений без изменения регистра,
   внутренних пробелов и исходного словаря.
   Проверки работают с отдельными временными базами на синтетических данных.

4. **AI-инструменты:** использован Codex для чтения README и кода, подготовки плана,
   изменения обработчика, дополнения тестов и создания этого отчёта.
   Codex выполнил автоматические проверки, перечисленные выше.

5. **Git:** в исходной папке отсутствует Git-репозиторий. Коммит не создавался;
   подтверждение работы с Git для сдачи пока не подготовлено.

6. **Оставшиеся ограничения и риски:**
   - Ошибки диска, недоступная БД и превышение времени ожидания блокировки SQLite
     распространяются как исключения; они не маскируются под некорректные входные поля.
     Нагрузочное тестирование не выполнялось.
   - Прямая запись сторонним SQL-кодом может обойти проверку полей и правило одного
     уведомления на заявку: `FOREIGN KEY` и уникальный индекс по `notifications.lead_id`
     не добавлялись. Обработчик обеспечивает это правило своей транзакцией.
   - Фактическая отправка уведомлений не входит в задание.

7. **Фактическое время работы:** примерно 60 минут на реализацию, проверки и отчёт;
